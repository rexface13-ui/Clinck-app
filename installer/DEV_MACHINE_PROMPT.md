# Prompt to use on the DEV machine

اعمل نسخ للنص التالي واستخدمه مع Claude Code على جهاز التطوير (مش جهاز العيادة):

---

هذا مشروع DentaFlow (نظام إدارة عيادة أسنان — Laravel backend + React/Vite frontend).
عندي ريبو تطوير رئيسي: `github.com/rexface13-ui/Clinck-app` (فيه `frontend/src` الكامل
+ `build.bat` اللي بيعمل `npm run build` وبينسخ الناتج + الباك إند + php83 لمجلد
`../DentaFlow-deploy` جاهز للتوزيع).

عندي كمان ريبو نشر (deployment) خاص بكل زبون، مثلاً: `github.com/rexface13-ui/YousefClinic`
(فرع `main`) — بيشتغل هيك:

- عند الزبون (جهاز العيادة)، فيه زر "تحديث النظام" في صفحة الإعدادات (وسكربت بديل
  `installer\update.bat`) بيعمل: `git fetch` + `git reset --hard origin/main` ثم
  `composer install --no-dev` ثم `php artisan migrate --force`.
- **مهم جداً ومصدر مشكلة حقيقية صارت:** سكربت التحديث عند الزبون **لا يبني الفرونت
  إند** (مفيش `npm run build` فيه) — هو بس بيسحب الكود وبيثبّت مكتبات PHP ويشغّل
  migrations. و`frontend/.gitignore` (المنسوخ من ريبو التطوير) بيستبعد `dist` بشكل
  افتراضي. يعني **أي `git push` عادي لريبو الزبون مش هيرفع `frontend/dist` خالص**،
  وأول ما الزبون يعمل تحديث، الواجهة القديمة بتنمسح (لأنها كانت موجودة محلياً بس
  مش متتبّعة) ومفيش نسخة جديدة تحل مكانها → شاشة بيضاء. (فيه الآن حماية على جهاز
  الزبون بترجّع نسخة احتياطية قديمة تلقائياً بدل ما تسيب الشاشة فاضية تماماً، لكن
  النسخة القديمة دي ناقصة آخر الميزات لحد ما نرفع نسخة جديدة صح.)
- الحل: **لازم أعمل force-add لـ `frontend/dist` عند الرفع لريبو الزبون** (مش ريبو
  التطوير الرئيسي — هناك سيبها متجاهلة زي ما هي، لأنه ريبو مصدر مش توزيع):
  ```bash
  npm run build          # داخل frontend/
  git add -f frontend/dist
  git add -A
  git commit -m "..."
  git push
  ```
- مجلد `backend/vendor/` و`php83/` (رنتايم PHP) متجاهلين من Git في كل الريبوهات
  (كبار وما بتتغيّر) — مش المفروض يترفعوا أبداً، ولا حتى بـforce.
- ملف `backend/.env` متجاهل من Git تماماً (فيه أسرار زي DB password وGitHub token)
  — منعمل عليه أي تعديل ولا نرفعه أبداً.

المطلوب مني (كمساعد) قبل أي `git push` لريبو زبون:
1. أسأل بوضوح: هل التعديل فيه تغيير بالفرونت إند؟ لو أيوه، أتأكد إنه مبني فعلاً
   (`npm run build`) وإني عملت `git add -f frontend/dist` صراحة قبل الـ commit
   (لأنه متجاهل افتراضياً ومش هينضاف بـ `git add -A` وحدها).
2. أعمل `git status` وأتأكد ما فيش `.env` ولا أي سر بينضاف بالغلط للـ commit.
3. أكتب commit message واضح يشرح "ليه" مش بس "إيش".
4. أعمل push عادي (fast-forward) — **بدون أي `--force`** إلا لو صرّحت أنا بذلك صراحة،
   لأن جهاز العيادة بيعتمد كلياً على تاريخ هذا الفرع.
5. بعد الـ push، أفتكر إني (كصاحب المشروع) لازم أروح لجهاز العيادة وأضغط زر
   "تحديث النظام" ثم أعيد تشغيل النظام (إغلاق نوافذ Backend/Frontend وTelegram Bot
   وتشغيل `start.bat` من جديد) عشان التحديث يتطبّق فعلياً.

خد بالك: كل ريبو زبون هو **ريبو توزيع (deploy) خاص بزبون واحد**، مختلف عن ريبو
التطوير الرئيسي `Clinck-app` — لو مش متأكد أي ريبو زبون المقصود بالـ push، اسألني
قبل أي حاجة.
